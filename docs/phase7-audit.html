How this audit was actually run

Ten specialised audit agents were launched in parallel. All ten died on the session rate limit within minutes, having produced nothing usable — the cost problem that was flagged before launching them. The audit was then performed directly. This is recorded because a report that implied ten teams reviewed this code would be false.

What the defects have in common

Six of the seven produced a confident wrong answer, a silent loss, or a bypass — not a crash, not an error message. That is the failure class a research engine has to be defended against, because nothing in the output looks wrong. The seventh was an outright crash, and was the easiest to find precisely because it announced itself.

Findings

F4 Large corpora crashed the process crashfixed

Conflict detection appended its results with push(...array), which passes every element as a separate argument. Six hundred disagreeing evidence items exceeded the argument limit and overflowed the call stack, taking down the run.

Before 
evidence=50    conflicts=1072   43ms
evidence=200   conflicts=17143  633ms
evidence=600   RangeError: Maximum call stack size exceeded

Fix: appended with a loop. Test: 2,000 disagreeing items must not throw.

F5 Disagreements grew quadratically highfixed

Value conflicts are found pairwise, so 200 pieces of evidence produced 17,143 "conflicts". That is not a report anyone can read, and it is the shape that led to the crash above.

After 
evidence=50     conflicts=13  39ms
evidence=200    conflicts=13  47ms
evidence=600    conflicts=13  46ms
evidence=2000   conflicts=13  48ms

Fix: detection is capped per claim and the pair scan is bounded to the strongest evidence. A truncated set is declared as a summary conflict — “N further disagreements are not listed individually; the sources do not agree” — rather than silently cut. A two-source disagreement is still reported in full, with both figures.

F3 One oversized artifact destroyed all five data lossfixed

A deep run's evidence.json reached ~533 KB and sources.json ~294 KB against the ArtifactManager's 256 KB inline ceiling. They were written sequentially under one shared catch, so the first oversized write aborted the rest. A run could write one artifact and report zero — losing the data and misreporting what it had.

Reproduction 
untrimmed:  1,189,793 bytes   → rejected, run reports 0 artifacts
trimmed:      148,698 bytes   → accepted, 50 of 400 kept
                               + {"kept":50,"total":400,"reason":"trimmed"}

Fix: each artifact is written independently, payloads are trimmed to fit, and a trimmed payload carries a truncated note. A record that does not say it is truncated is worse than a missing one.

F1 DNS-based SSRF bypass securityfixed

The URL screen inspects the host as written, so it catches 127.0.0.1 in every encoding — decimal, hex, octal, IPv4-mapped IPv6. It did not catch a public name that resolves to a private address.

Allowed before the fix 
http://localtest.me/                  → 127.0.0.1
http://169.254.169.254.nip.io/        → cloud metadata endpoint

Fix: the known wildcard-DNS services are blocked by name — but that is a blocklist, and blocklists are never complete. The real defence is the new screenResolvedAddress(ip), which the code that actually opens the socket calls with what DNS returned.

F2 Redirects were never screened securityfixed

Only the initial URL was checked. A page on an allowed domain could redirect to the metadata endpoint and defeat the screen entirely — the textbook bypass, and the code's own comment already mentioned "a redirect target" while nothing handled one.

Fix: screenRedirect(from, to) screens every hop against the same rules, bounded by MAX_REDIRECTS.

This one is a contract, not an enforcement. The core performs no network I/O by design, so F1 and F2 can only be honoured by the provider that does the fetching. The guards are exported and the obligation is now stated in searchProvider.js, where a provider author reads it — but a provider that ignores it is still vulnerable. Verify this when you wire a real search backend.

F6 An href sink trusting upstream validation defence in depthfixed

The research panel assigned a source URL straight to a.href on the strength of upstream screening alone. No exploit path was found — the screen does reject javascript: — but a sink that trusts its input is one refactor away from being the hole.

Fix: the scheme is validated at the sink, and a non-linkable URL is shown as text rather than hidden, so a reader can still see what the research cited.

F7 Fourteen dead exports, two of them live logic written twice maintainabilityfixed

The specification asks for no dead code, and the layer had fourteen exports referenced only by their own export line. They were not all the same thing:

  • Two were duplication. isAssertable is the claim schema's answer to "may this be stated plainly?", and both the synthesizer and the quality evaluator re-derived it from status comparisons — how two layers drift into disagreeing about what an answer may assert.
  • Three were an advertised feature that did not work. Asking the renderer for footnote citations produced [1] markers in the prose with [^1]: definitions underneath: a document whose footnotes point at nothing.
  • One was a real gap. A file citation printed a bare filename and lost the line range — the part a reader needs to check it.
  • Eight were speculation and are deleted rather than kept as surface nobody exercises.

A test now fails the build if a research export goes unreferenced again. Writing it surfaced an eighth defect: ARTIFACT_INLINE_BUDGET was never re-exported from the barrel, so any consumer comparing against it was comparing against undefined.

Risks that remain

The web path has never run against a real provider

This is the largest gap and it has not moved. The core imports no HTTP client by design, the app ships no search key, and this environment's proxy blocks the open web — the attempt was made and returned 403. Every web test runs against a fake provider. Retries, redirects, rate limits, malformed JSON, gzip, character encodings and slow responses are untested against real-world behaviour. Wiring a real backend is the next piece of work, and F1/F2 must be verified at that point.

Two dependency advisories are open

Neither is reachable through this app's code paths, but both are present in the shipped tree. The transformers upgrade is a real piece of work, not a version bump.

The app was never launched

Nothing here ran Electron. Cross-platform correctness was established by static audit and by feeding Windows-shaped paths to the pure functions — a real check, but not a run. The research panel's rendering has never been seen on screen.

Classification is lexical

The classifier and query decomposition work on structured English. Another language or an unusual phrasing will be categorised less accurately. The refine hook exists for a model-backed improvement but is not wired by default.
